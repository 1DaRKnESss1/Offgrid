# Offgrid

Локальний голосовий асистент для Windows 11, який живе в треї. Усе працює на цьому комп'ютері:
модель — через Ollama, розпізнавання й синтез мови — локальними Whisper і Piper. Хмарних сервісів немає.

Стан: **етап 4, жива розмова** — команди голосом і текстом, відповідь текстом і голосом, інструменти, білі списки
з редагуванням у панелі, підтвердження, журнал.

## Запуск

Потрібні Node 24+ і запущена Ollama з моделлю `qwen3.5:9b`. Для голосу — Python 3.12 з пакетами
`faster-whisper`, `piper-tts`, `sounddevice`, `numpy`, моделі Whisper (`medium` і `small`) та голос Piper.

```
powershell -ExecutionPolicy Bypass -File scripts\setup-webview2.ps1
npm start
```

Перша команда потрібна один раз: вона завантажує три бібліотеки Microsoft для вікна панелі (WebView2 SDK
з nuget.org, близько 1 МБ після розпакування) і перевіряє їхні підписи. Сторонніх пакетів npm застосунок
не має.

### Чому не Electron

Спершу застосунок був на Electron, але його `electron.exe` не має цифрового підпису, і Smart App Control
у Windows 11 з часом почав його блокувати. Тепер оболонка складається лише з того, чому Windows уже
довіряє — приблизно так само, як влаштований Tauri:

| Частина | Чим зроблена |
|---|---|
| логіка: агент, інструменти, захист | Node.js (`src/app/main.js`) |
| вікно панелі | WebView2 — рушій, вбудований у Windows 11 |
| нативна частина: вікно без рамки, трей, глобальна клавіша, діалоги | скрипт PowerShell (`shell/host.ps1`) |
| інтерфейс | HTML/CSS/JS у `src/renderer` |

Процеси спілкуються так: Node керує оболонкою рядками JSON через її stdin/stdout, а панель звертається
до Node через локальний сервер на `127.0.0.1`.

Іконка з'явиться в треї. Клацання по іконці показує або ховає панель.

`Ctrl + Shift + Space` — говорити: асистент слухає до паузи (або до повторного натискання), показує
розпізнаний текст і відповідає. Те саме робить кнопка 🎤 у панелі.

Розмова голосом:

- відповідь з'являється й звучить із першого речення, поки модель ще пише решту;
- після відповіді асистент ще 5 секунд слухає продовження без клавіші; мовчиш — розмова закінчилась.
  Так він слухає щонайбільше 4 рази поспіль, далі знову потрібна клавіша;
- натиснути клавішу під час відповіді означає перебити: він замовкає й одразу слухає тебе
  (працює і тоді, коли модель ще дописує відповідь);
- `Esc` (коли панель у фокусі) або кнопка ■ зупиняє все.

Кнопка 🔊 вмикає й вимикає озвучення; «продовження без клавіші» вимикається в ⚙ → «Інше».
Довгі відповіді озвучуються не повністю (до ~1500 символів). Поки голос завантажується
(10–25 секунд після запуску) або якщо він вимкнений, клавіша просто показує панель.

| Команда | Що робить |
|---|---|
| `npm start` | запускає застосунок |
| `npm test` | тести захисту (білі списки, шляхи, підтвердження) |
| `python speech\gpu_check.py` | перевіряє розпізнавання на відеокарті: швидкість, точність, скільки відеопам'яті займає |
| `npm run speech-selftest` | перевіряє Whisper і Piper без мікрофона й без звуку |
| `node scripts/wake-check.js` | перевіряє режим «відгук на ім'я» без звуку; `--say` — чекає 30 с, доки ти назвеш ім'я |
| `npm run speech-check` | запускає мовний сервіс і пише з мікрофона (`-- --speak` — ще й озвучує фразу) |
| `npm run tool-eval` | на повторах перевіряє, що модель справді викликає інструменти (запускати після зміни промпту) |
| `node scripts/sleep-check.js` | заміряє, скільки відеопам'яті звільняє сон і скільки триває пробудження |
| `npm run smoke` | проганяє агента зі справжньою моделлю; запуск програм і відкриття файлів замінено заглушками |

## Що де лежить

```
src/app        головний процес: хід розмови, сервер панелі (server.js), керування оболонкою (host.js)
shell          нативна оболонка на PowerShell: вікно WebView2, трей, глобальна клавіша, діалоги
src/agent      цикл агента, клієнт Ollama, системний промпт
src/tools      інструменти: програми, гучність і система, файли, нотатки, інтернет
src/security   білі списки, перевірка шляхів, підтвердження, журнал
src/speech     клієнт мовного сервісу (запуск, запис, озвучення)
speech         мовні сервіси на Python: мікрофон -> текст (Whisper), текст -> голос (Piper або OmniVoice)
src/renderer   панель: розмова, налаштування, журнал (HTML/CSS/JS без фреймворків)
config         типові налаштування
data           твої налаштування, журнал, нотатки (не потрапляє в git)
```

## Налаштування й білі списки

Програми, папки, типи файлів і гарячу клавішу можна змінювати просто в панелі: кнопка ⚙ у шапці
(або «Налаштування…» в меню іконки в треї). Програму чи папку ти обираєш у системному вікні вибору;
зміни діють одразу. Кнопка 📋 показує журнал дій.

Усе це зберігається у `data/settings.json` (створюється при першому запуску з `config/default.json`).
Файл можна правити й вручну, а потім натиснути «Перечитати налаштування» в меню трею.
Панель записує файл у стандартному вигляді, тож ручне форматування після зміни з панелі зникає.

- `apps` — програми, які можна відкривати. `exe` — назва `.exe` або повний шлях, без аргументів.
  Якщо вказано `process`, програму можна й закривати.
- `folders` — папки, де асистент шукає й відкриває файли. `~/Documents` означає папку користувача.
- `folders` приймає лише наявні папки на локальних дисках. Корінь диска, усю папку користувача,
  системні та мережеві папки дозволити не можна.
- `fileTypes` — типи файлів, які можна відкривати; `readableTypes` — які можна читати.
  Вибирати можна лише з документів, зображень, звуку, відео й простого тексту. Програми, скрипти,
  ярлики, веб-сторінки й архіви дозволити не можна.
- `confirm` — посилити підтвердження для інструмента: `"open_app": "always"`
  (значення: `content`, `tainted`, `always`). Послабити не можна.
- `hotkey` — гаряча клавіша, наприклад `Control+Shift+Space` (модифікатори `Control`, `Alt`, `Shift`, `Super`).
- `speakReplies` — озвучувати відповіді (те саме, що кнопка 🔊).
- `idleUnloadMinutes` — через скільки хвилин без команд звільняти пам'ять (0 — ніколи);
  `yieldToOtherApps` — звільняти її, коли відеопам'яті бракує іншій програмі.
- `gpuLayers` — скільки шарів моделі асистента класти на відеокарту: `"auto"` (підбирається під вільну
  відеопам'ять при запуску) або число від 0 до 99.
- `followUp` — після озвученої відповіді слухати продовження без клавіші.
- `wake` — відгук на ім'я: `enabled` (типово `false`), `name` (типово «Офгрід»), `aliases` — як іще це
  ім'я може бути записане. Докладніше — нижче, у розділі «Відгук на ім'я».
- `speech` — голос: `python`, папка моделей `whisperDir`, точна модель `whisperModel`, швидка модель
  для тексту наживо `liveModel` (порожній рядок вимикає його), файл голосу `piperVoice`, темп `speed`
  (більше — повільніше); `device` — де розпізнавати: `auto` (відеокарта, якщо можна), `cpu` або `gpu`;
  `gpuModel` — модель для відеокарти. `"enabled": false` повністю вимикає голос. Якщо розділу `speech` у файлі
  немає, береться типовий — це єдиний розділ, для якого так зроблено, бо він не є білим списком.
  Якщо голос не запустився, виправ причину й натисни «Перечитати налаштування» в меню трею.

Неправильні записи відкидаються, а панель показує, що саме не так. Помилка в налаштуваннях ніколи
не розширює дозволи: якщо розділ білого списку зник чи названий з одруківкою, цей список порожній; якщо файл
зіпсовано, лишаються попередні налаштування (а на старті — порожні списки).

## Острівець

Асистент живе на екрані маленькою «пігулкою» поверх вікон (типово — вгорі по центру) і сам показує, що робить:

- **спокій** — «Offgrid», або «Скажи «Офгрід»», коли ввімкнено відгук на ім'я, або «Сплю»;
- **слухає** — хвиля звуку й текст, який розпізнається наживо;
- **думає / виконує** — що саме робить;
- **відповідає** — текст відповіді (останні слова, поки звучить голос; після відповіді ще кілька секунд);
- **просить дозволу** — що хоче зробити й кнопки «Дозволити / Відхилити»;
- коротке повідомлення чи помилка — на кілька секунд.

Клацни по острівцю — він розкриється в повну панель (розмова, поле вводу, налаштування, журнал); Esc, ✕ або
клік в іншому вікні згортають її назад. Острівець можна перетягнути мишею будь-куди (розкриту панель — за
заголовок), місце запам'ятовується у `data/window.json`. Коли інша програма займає весь екран (гра, відео),
острівець ховається й повертається, щойно вона піде з переднього плану.

Вікно острівця прозоре: видно лише саму пігулку, а кліки поруч із нею доходять до програм під нею. Малюється
він без відеокарти, тож пам'яті в моделі не забирає. `prototype/` — перший макет цього вікна, до застосунку
не підключений.

## Відгук на ім'я

Вимкнено, доки ти сам не ввімкнеш: ⚙ → «Інше» → «Відгукуватись на ім'я» або однойменний пункт у меню трею.
Тоді гаряча клавіша вже не обов'язкова: скажи «Офгрід, котра година» — або лише «Офгрід» і команду після
паузи. Далі розмова йде як звичайно (асистент кілька секунд слухає продовження після своєї відповіді), а
закінчується тишею або фразою на кшталт «повернусь потім», «на цьому все», «дякую, це все». Така фраза до
моделі не передається. Ім'я можна змінити там само (слово від трьох літер); що незвичніше ім'я, то менше
хибних спрацювань.

Що при цьому відбувається з мікрофоном:

- Поки режим увімкнений і асистент не зайнятий, мовний сервіс слухає мікрофон безперервно. Кожну почуту
  фразу він розпізнає **на цьому комп'ютері** й шукає в ній ім'я. Якщо імені немає — текст тут же
  відкидається: він не залишає процес мовного сервісу, не потрапляє ні до моделі, ні в журнал, ні на диск.
  Звук теж ніде не зберігається.
- У підказці іконки в треї та внизу панелі видно, що асистент зараз чекає на ім'я.
- Під час відповіді асистента очікування вимкнене — на власний голос він не відгукується.
- Уві «сні» ім'я слухає мала модель на процесорі, відеопам'ять лишається вільною; команда після імені
  розпізнається вже точною моделлю, тож перша відповідь після сну довша на кілька секунд.
- Розпізнавання кожної фрази коштує трохи ресурсів відеокарти (або процесора вві сні). Якщо в кімнаті
  постійно хтось говорить чи грає звук — це помітне навантаження; тоді режим краще вимкнути.
- Ім'я, вимовлене у відео чи кимось іншим, теж розбудить асистента. Небезпечні дії однаково потребують
  твого дозволу кнопкою в панелі — голосом їх підтвердити не можна.

## Асистент пропонує — ти дозволяєш

Білі списки можна поповнювати й голосом: «додай Discord у дозволені програми», «дозволь папку D:\Projects»,
«дозволь файли pdf». Асистент при цьому нічого не додає сам — він лише готує пропозицію:

- **програму** шукає код, а не модель: за назвою серед ярликів меню «Пуск» і робочого столу та серед
  встановлених ігор Steam; якщо схожих кілька — перепитує, якщо не знайдено — каже про це;
- **папку** приймає повним шляхом або однією з назв: downloads, documents, desktop, pictures, music, videos;
- **тип файлів** — лише з того самого переліку, що й на екрані налаштувань.

Далі в острівці з'являється запит із повним шляхом, і рішення приймаєш ти кнопкою — завжди, хоч би як були
налаштовані підтвердження, і тільки кнопкою, не голосом. Запис робить той самий код, що й екран налаштувань,
тож системну папку, скрипт чи мережевий шлях він не прийме, навіть якщо натиснути «Дозволити». Якщо в цій
розмові асистент уже читав файли чи сайти, запит окремо попереджає: прохання могло прийти з прочитаного тексту.
Додану програму асистент зможе відкрити з наступної команди.

Писати й запускати власний код («додавати собі інструменти») асистент не може, і це навмисно.

## Асистент бачить екран

«Офгрід, що в мене на екрані?», «що тут написано?», «що це за помилка?» — асистент робить знімок екрана, на
якому зараз миша, і відповідає на питання про нього. Модель `qwen3.5:9b` уміє розглядати зображення, окрема
модель не потрібна. Відповідь приходить приблизно за 12 с (знімок зменшується до 1280 пікселів завширшки;
дрібний текст модель може не розібрати).

Що при цьому з приватністю й безпекою:

- знімок не залишає комп'ютер і не зберігається: тимчасовий файл видаляється одразу, у журнал іде лише
  питання й розмір знімка, а не побачене;
- острівець на мить ховається, щоб не потрапити в кадр;
- текст з екрана — такі самі недовірені дані, як вміст файлу. Знімок розглядає окремий запит до моделі, у
  якого немає жодних інструментів, а після погляду на екран запис нотаток, пошук і відкриття сайтів потребують
  твого дозволу кнопкою (до «Нової розмови»);
- якщо в розмові асистент уже читав файли чи сайти, сам погляд на екран теж потребує дозволу.

## Як влаштований захист

- Модель може лише викликати інструменти зі списку. Кожен виклик проходить через одну точку
  (`src/security/policy.js`): перевірка, за потреби — підтвердження, виконання, запис у журнал.
- **Завжди з підтвердженням:** закриття програми, видалення нотатки.
- **Текст із файлів — це дані, а не команди.** Щойно асистент побачив назви файлів чи нотаток,
  розмова позначається («бачив файли»), і до кінця розмови запис нотаток, пошук і відкриття сайтів
  потребують твого дозволу. Так вставлена у файл «інструкція» не може нічого записати чи винести назовні.
  Якщо асистент прочитав ще й вміст файлу чи нотатки, дозволу потребує також відкриття файлів.
  Відкриття програм і папок з білих списків лишається без запитань. «Нова розмова» скидає позначку.
- Дозвіл дається лише кнопкою в панелі. Модель до цього каналу доступу не має. Після першої відмови
  решта дій того самого запиту відхиляється вже без запитань.
- Шлях до файлу спершу перевіряється як текст (лише локальний диск, лише всередині дозволеної папки)
  і тільки потім — на диску, з розкриттям посилань і точок з'єднання. Мережеві шляхи не приймаються.
- Асистент пише лише в `data/` всередині проєкту. Видалена нотатка переміщується в `data/notes/_кошик`.
- Пошук в інтернеті лише відкриває сторінку у твоєму браузері; вмісту сторінок асистент не бачить.
- Панель — це сторінка у вікні WebView2 без доступу до диска й системи: вона може лише надсилати запити
  локальному серверу застосунку. Сервер слухає тільки `127.0.0.1` на випадковому порту. При запуску панель
  отримує ключ, який діє рівно один раз і одразу міняється на окремий секрет у cookie; ключ передається
  оболонці через stdin, а не в командному рядку. Сервер перевіряє адресу й походження кожного запиту
  і приймає тільки JSON. Сторінка, відкрита в браузері, не може ні читати події, ні давати команди.
  Від іншої програми, запущеної під твоїм же користувачем, це не абсолютний захист: така програма
  й так може читати файли проєкту та пам'ять процесів. Якщо комп'ютером користуються інші облікові
  записи, перевір права на папку проєкту — за замовчуванням на несистемному диску вона може бути
  доступна всім користувачам. Вікно не переходить на інші адреси, не відкриває нових вікон і відхиляє всі запити дозволів.
  Увесь текст у панелі виводиться як текст, не як розмітка.
- Мовний сервіс слухає лише `127.0.0.1` на випадковому порту й відповідає тільки на запити з одноразовим
  токеном, який знає лише застосунок. Моделі беруться з диска; звернення до Hugging Face вимкнено.
  Сервіс завершується разом із застосунком.
- «Продовження без клавіші» означає, що 5 секунд після відповіді мікрофон слухає сам. Усе, що він
  почує в цей час (зокрема чужий голос у кімнаті), буде сприйнято як твоя команда. Небезпечні дії
  все одно потребують кнопки, а правила про сторонній текст діють як завжди. Вимикається в ⚙ → «Інше».
  Щоб це не тривало без людини (скажімо, поруч говорить телевізор), без клавіші асистент слухає не
  більше 4 разів поспіль, початком мови вважає лише стійкий звук, а між власним голосом і записом
  робить паузу, щоб не почути самого себе.
- Слухати й говорити одночасно сервіс не вміє навмисно: початок запису обриває озвучення, щоб асистент
  не записав власний голос як команду.
- Розпізнаний голос — це твоя команда, як і надрукований текст. Дозвіл на небезпечну дію все одно
  дається лише кнопкою, не голосом.
- Зміни з панелі проходять ту саму перевірку, що й файл налаштувань: дозволити через панель те, що
  не можна дозволити вручну, неможливо. Модель до налаштувань доступу не має — жодного інструмента
  для цього не існує. Зміни діють одразу, навіть посеред запиту, який уже виконується. Кожна зміна налаштувань потрапляє в журнал.
- Журнал дій: `data/actions.log`, один рядок JSON на дію; після 2 МБ переїжджає в `actions.old.log`.

## Відеокарта

На 8 ГБ відеопам'яті все вирішує розподіл, тому застосунок ділить її сам.

- **Розпізнавання мови на відеокарті.** Якщо в `speech\vendor` лежать бібліотеки NVIDIA, Whisper
  (`large-v3-turbo`) працює на відеокарті: близько 0,2 секунди на фразу замість 3 на процесорі,
  1,2 ГБ відеопам'яті. Текст наживо тоді дає та сама точна модель. Бібліотеки (2 ГБ на диску) ставляться
  в папку проєкту, а не в систему:

  ```
  python -m pip install --target speech\vendor nvidia-cublas-cu12 nvidia-cudnn-cu12
  ```

  Без них, або якщо відеокарта не запустилась, розпізнавання саме працює на процесорі, як раніше.
  Щоб прибрати — видали папку `speech\vendor`.
- **Модель асистента.** При запуску (і після «Перечитати налаштування») застосунок дивиться, скільки
  відеопам'яті зайнято всім іншим, і каже Ollama, скільки шарів моделі класти на відеокарту. Якщо модель
  вміщається цілком, вона працює близько 59 токенів/с; автоматичний розподіл самої Ollama давав 30,
  а переповнення відеопам'яті — 10–15. Для заміру модель один раз вивантажується, тож перша відповідь
  після запуску довша на кілька секунд. Рішення видно в журналі дій.
- **Розподіл рахується при запуску й після кожного пробудження.** Якщо відеопам'ять уже зайнята іншими
  програмами, на відеокарту піде менше шарів моделі — повільніше, але без обвалу; панель про це скаже.

### Якісний голос (OmniVoice)

Типовий голос Piper швидкий, але звучить просто. Якщо встановити OmniVoice, асистент говорить ним:
це модель іншого класу, з живими інтонаціями, і голос у неї задається зразком на кілька секунд.

Встановлення (близько 11 ГБ на диску: PyTorch, пакети й модель; усе в папці проєкту, не в системі):

```
python -m venv speech\tts-env
speech\tts-env\Scripts\python.exe -m pip install torch==2.8.0+cu128 torchaudio==2.8.0+cu128 --extra-index-url https://download.pytorch.org/whl/cu128
speech\tts-env\Scripts\python.exe -m pip install omnivoice soundfile sounddevice
speech\tts-env\Scripts\python.exe speech\omni_check.py
```

Остання команда завантажує модель (у `E:\AI\omnivoice`), кладе зразки в `data\voice-samples` і показує,
скільки відеопам'яті та часу потрібно. Далі з вподобаного зразка робиться постійний «відбиток» голосу:

```
speech\tts-env\Scripts\python.exe speech\make_voice.py <зразок.wav> "<точний текст зразка>"
```

Відбиток зберігається в `data\voice\offgrid-voice.pt`. Щоб змінити голос, достатньо створити новий
відбиток і натиснути «Перечитати налаштування». Бери лише власний, згенерований або дозволений тобі голос.
Модель OmniVoice має некомерційну ліцензію (CC-BY-NC).

Як це вміщається у відеопам'ять:

- розпізнавання й голос ніколи не працюють одночасно, тому **займають одне місце по черзі**: поки модель
  асистента думає, розпізнавання звільняє відеокарту, а голосова модель заходить на неї (0,3 с), і навпаки;
- постійно сервіс голосу тримає близько 0,9 ГБ; разом із цим моделі асистента лишається менше місця,
  ніж із Piper. Скільки саме — залежить від інших програм: на чистій системі модель вміщається майже
  цілком, а з шпалерами Wallpaper Engine, браузером і Discord (близько 1,8 ГБ) — 19 шарів із 33;
- якщо озвучення вимкнене кнопкою 🔊, сервіс голосу не запускається зовсім, і вся відеопам'ять дістається
  моделі;
- синтез фрази — 0,5–0,8 с; на процесорі цей голос не працює (8–17 с на фразу).

Якщо середовища, моделі чи відеокарти немає, або сервіс не запустився, асистент говорить голосом Piper.
Примусово вибрати рушій: `speech.voice.engine` — `auto`, `piper` або `omnivoice`.

### Сон: комп'ютер вільний, коли асистентом не користуються

Модель і розпізнавання займають близько 6 ГБ відеопам'яті, лише поки вони завантажені. Тому асистент
«засинає» і звільняє її (заміряно: 5,9 ГБ за півтори секунди):

- **після простою** — через 5 хвилин без команд (змінюється в ⚙ → «Інше», можна вимкнути);
- **на вимогу** — меню іконки в треї → «Звільнити відеопам'ять (заснути)», наприклад перед грою;
- **коли відеопам'яті бракує іншій програмі** — якщо вільного лишилося менше 200 МБ два виміри поспіль
  (запустилась гра), асистент поступається сам. Вимикається там само.

Прокидається він із першою ж командою: слухати починає одразу, а модель повертається в пам'ять у фоні
приблизно за 4 секунди. У шапці панелі й у підказці іконки в цей час написано «Спить».
Звичайну пам'ять сон майже не звільняє (мовний сервіс лишається запущеним, близько 1,5 ГБ) — це плата
за швидке пробудження. Сервіс якісного голосу після простою теж лишається (ще близько 0,9 ГБ відеопам'яті),
а от коли пам'ять звільняють кнопкою чи для іншої програми — зупиняється зовсім і після пробудження
запускається заново за ~20 секунд; у цей час відповіді звучать голосом Piper.

## Відомі обмеження

- Вікно контексту моделі — 4096 токенів, з них близько 2500 займають промпт і опис інструментів.
  Тому асистент пам'ятає лише кілька останніх реплік і читає з файлу перші 1500 символів.
- Перша відповідь після запуску Ollama може тривати понад хвилину: модель завантажується в пам'ять.
- **Відеопам'ять.** Поки асистент не спить, модель і розпізнавання займають майже всі 8 ГБ. Якщо відеокарту навантажує щось іще (гра, відео),
  модель витісняється у звичайну пам'ять: відповіді тривають хвилинами, а Ollama може впасти при
  завантаженні. Застосунок один раз повторює спробу сам.
- **Швидкість розпізнавання на процесорі** (якщо відеокарта для нього недоступна). Точна модель `medium` розпізнає фразу
  близько 3 секунд (4–5, якщо процесор зайнятий), тому під час запису текст показує швидка `small`
  (1–2 секунди, з помилками), а потім його замінює точний. Щоб скоротити очікування, точне
  розпізнавання починається вже під час короткої паузи в мовленні, а кінцем фрази вважається 1 секунда
  тиші. Для цього `medium` завантажена двічі (близько 1 ГБ пам'яті). `large-v3-turbo` на цьому
  процесорі повільніша (близько 7 секунд). Перебити відповідь голосом не можна — лише клавішею:
  мікрофон чув би самого асистента.
- **Модель інколи «розповідає», а не робить.** Посеред розмови вона могла сказати «блокнот відкрито»
  чи «зараз перевірю час», нічого не викликавши. Тому до кожного запиту додається коротке нагадування
  про інструменти, а якщо модель усе одно лише описала намір, агент один раз вимагає виконати;
  `npm run tool-eval` показує 47–48 правильних із 48, тобто зрідка таке ще трапляється — у журналі дій видно,
  що було зроблено насправді.
- Захист від вставлених у файли інструкцій тримається на коді (підтвердження), а не на слухняності
  моделі. Назви файлів і вміст вона бачить і може переказати неточно.
