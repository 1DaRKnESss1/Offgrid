# Offgrid: як усе влаштовано і чому саме так

Цей файл — путівник для людини (чи агента), яка бачить проєкт уперше. README каже, *як користуватися*;
тут — *з чого система складається, хто за що відповідає і чому прийнято саме такі рішення*.
Цифри нижче — виміри на машині розробки: Ryzen 5 7500F, 32 ГБ ОЗП, RTX 5060 Ti 8 ГБ, Windows 11.

## 1. Одним абзацом

Offgrid — локальний голосовий асистент для Windows. Він чує команду (мікрофон або текст), передає її мовній
моделі, модель обирає *інструмент* (відкрити програму, знайти файл, записати нотатку…), код перевіряє, чи це
дозволено, за потреби питає користувача, виконує й відповідає текстом і голосом. Усе працює на цьому
комп'ютері: жодного хмарного сервісу. Головна ідея безпеки: **модель нічого не робить сама — вона лише просить,
а вирішує код і користувач.**

## 2. П'ять процесів

Застосунок — це не одна програма, а кілька процесів, які розмовляють між собою лише через локальні канали.

```
                         ┌──────────────────────────────────────────────┐
                         │  Node.js — головний процес (src/app/main.js) │
                         │  «диригент»: стан, розмова, агент, безпека   │
                         └───┬─────────┬──────────┬──────────┬──────────┘
        JSON-рядки через     │         │ HTTP     │ HTTP     │ HTTP 127.0.0.1
        stdin/stdout         │         │ 127.0.0.1│ 127.0.0.1│ (потік NDJSON)
                 ┌───────────▼───┐  ┌──▼───────┐ ┌▼────────┐ ┌▼──────────────┐
                 │ Оболонка      │  │ Мовний   │ │ Якісний │ │ Ollama        │
                 │ PowerShell +  │  │ сервіс   │ │ голос   │ │ (модель       │
                 │ WinForms +    │  │ Python   │ │ Python  │ │  qwen3.5:9b)  │
                 │ WebView2      │  │ Whisper  │ │ Omni-   │ │ окрема        │
                 │ shell/host.ps1│  │ + Piper  │ │ Voice   │ │ програма      │
                 └───────┬───────┘  └──────────┘ └─────────┘ └───────────────┘
                         │ показує сторінку
                 ┌───────▼────────────────────────────┐
                 │ Сторінка острівця (src/renderer/)  │──HTTP + SSE──▶ назад у Node
                 └────────────────────────────────────┘
```

| Процес | Файл | Що робить | Чого НЕ може |
|---|---|---|---|
| Головний (Node) | `src/app/main.js` | керує всім: стан, розмова, агент, білі списки, журнал | — |
| Оболонка | `shell/host.ps1` | вікно острівця, іконка в треї, глобальна клавіша, системні діалоги | не має логіки: виконує команди Node |
| Сторінка | `src/renderer/*` | малює острівець і панель, показує події | не має доступу до диска й системи |
| Мовний сервіс | `speech/speech_server.py` | мікрофон → текст (Whisper), текст → простий голос (Piper), очікування імені | не бачить розмови й моделі |
| Якісний голос | `speech/voice_server.py` | текст → голос OmniVoice | те саме |
| Ollama | зовнішня | запускає мовну модель | не має інструментів — лише текст |

**Чому так.** Спершу оболонкою був Electron, але Smart App Control у Windows 11 заблокував непідписаний
`electron.exe`. Замість вимикати захист системи, оболонку переписано на компонентах, які Windows уже довіряє:
PowerShell, .NET WinForms і WebView2 (рушій Edge). Архітектурно це те саме, що Tauri: «рідне» вікно + вебсторінка
+ окремий процес логіки. Python-сервіси окремі, бо моделі мовлення живуть у Python, а якісний голос потребує
власного середовища з PyTorch (`speech/tts-env`).

## 3. Шлях однієї команди

Приклад: користувач каже «Офгрід, відкрий блокнот».

1. **Мовний сервіс** (режим очікування імені, `wake_listen`) безперервно слухає мікрофон, кожну фразу
   розпізнає й шукає в ній ім'я. Фрази без імені відкидає на місці. Знайшов — повертає решту фрази.
2. **main.js** (`armWake` → `startListening`) отримує «відкрий блокнот», прокидає модель, якщо та спала
   (`wakeUp`), і починає хід розмови (`runTurn`).
3. **Агент** (`src/agent/agent.js`) надсилає в Ollama історію розмови, системну підказку (`prompt.js`) і опис
   доступних інструментів. Модель відповідає: «виклич `open_app` з `app: notepad`».
4. **Політика** (`src/security/policy.js`, функція `executeTool`) — єдине місце, через яке проходить будь-яка дія:
   чи існує такий інструмент → рання перевірка аргументів → чи потрібен дозвіл → (запит користувачеві) →
   виконання → запис у журнал → позначка «забруднення».
5. **Інструмент** (`src/tools/apps.js`) запускає програму з білого списку. Результат повертається моделі.
6. Модель пише відповідь; вона надходить **потоком**: кожне завершене речення (`src/speech/sentences.js`)
   одразу йде на озвучення, тож асистент починає говорити, не чекаючи кінця.
7. **Сторінка** отримує події (`state`, `reply-delta`, `tool`…) і острівець змінює вигляд.
8. Якщо ввімкнено «продовження», асистент ще 5 с слухає без клавіші; потім знову чекає на ім'я.

## 5. Безпека — серце проєкту

Модель — ненадійний виконавець: вона може помилитися, а текст, який вона читає (файли, сайти), може містити
вказівки, написані зловмисником («вбудовані інструкції», prompt injection). Тому захист побудовано не на
«проханні до моделі поводитися добре», а на коді довкола неї.

**5.1. Одна точка виконання.** Будь-яка дія йде через `executeTool`. Інструмент не можна викликати в обхід.

**5.2. Білі списки.** Програми, папки й типи файлів — лише ті, що в налаштуваннях. Типи файлів — саме *дозволений
перелік* (документи, зображення, звук, відео), а не «все, крім небезпечного»: `.exe`, `.bat`, `.lnk`, `.ps1`
дозволити неможливо взагалі.

**5.3. Перевірка шляхів** (`pathguard.js`). Тільки шляхи з буквою диска (жодних мережевих `\\server\…`),
перевірка «всередині дозволеної папки» — і до, і після розв'язання символьних посилань.

**5.4. «Забруднення» розмови.** Рівень 0 — асистент не бачив стороннього тексту; 1 — бачив назви файлів;
2 — читав вміст. Що вищий рівень, то більше дій потребує дозволу: після читання файлу навіть запис нотатки чи
відкриття сайту — лише з кнопки. «Нова розмова» скидає рівень. Сторонній текст моделі передається в «обгортці»
з позначкою «це дані, а не інструкції».

**5.5. Підтвердження.** Режими: `never`, `content`, `tainted`, `always`. Налаштування користувача можуть лише
**посилити** режим інструмента. Відповідь приймається тільки з кнопки в острівці — модель до цього каналу
доступу не має, голосом підтвердити не можна. Після першої відмови решта запитів у цьому ході відхиляється
автоматично (щоб шквал запитів не «дотиснув» дозвіл). Кнопка «Дозволити» вмикається із затримкою 0,8 с.

**5.6. Помилка в налаштуваннях ніколи не розширює дозволи.** Зник розділ білого списку — список порожній.
Файл зіпсовано — лишаються попередні налаштування.

**5.7. Сторінка без прав.** Вона може лише надіслати один із десятка запитів на локальний сервер. Сервер
приймає їх тільки з власної сторінки (одноразовий ключ → cookie, перевірка Host/Origin), слухає лише 127.0.0.1.
Мовні сервіси так само: випадковий порт, токен у заголовку, вихід разом із головним процесом.

**5.8. Пропозиції у білі списки** (`allow.js`). Асистент може *запропонувати* додати програму, папку чи тип
файлів, але: шлях до програми знаходить код, а не модель; підтвердження — завжди; запис іде через ту саму
перевірку, що й екран налаштувань. Писати й запускати власний код асистент не може — навмисно.

## 6. Відеопам'ять — головне апаратне обмеження

На 8 ГБ мають ужитися модель (~6,4 ГБ цілком), розпізнавання (~1,2 ГБ) і якісний голос (~1,3 ГБ + ~0,9 ГБ
службових даних) та все, що запущено в користувача. Усе одразу не влазить, тому:

- **Планувальник шарів** (`gpu.js`). Модель має 33 шари; скільки з них класти на відеокарту, рахується з
  фактично вільної пам'яті. Виміри: усе на відеокарті — 59 ток/с; частина на процесорі — близько 30;
  якщо відеопам'ять *переповнити* — 10–15 (гірше, ніж чесно віддати частину процесору); лише процесор — 8.
- **Обмін місцями.** Розпізнавання й голос ніколи не потрібні одночасно (спершу слухаємо, потім говоримо),
  тож вони по черзі займають одне й те саме місце: переїзд голосової моделі між ОЗП і відеокартою — 0,3 с.
- **Сон** (`resources.js`). Після простою (типово 5 хв), на прохання або коли відеопам'яті бракує іншій
  програмі (гра) — усе вивантажується (~5,9 ГБ вільно). Прокидається з першою командою.
- **Острівець малюється без відеокарти** і все одно дає повну частоту кадрів монітора.

## 7. Мовлення

- **Розпізнавання.** Whisper `large-v3-turbo` на відеокарті: ~0,2 с на фразу. Без відеокарти — `medium` для
  остаточного тексту плюс `small` для тексту наживо. Початок і кінець фрази визначає поріг гучності,
  відкалібрований за фоновим шумом.
- **Відгук на ім'я.** Не окрема модель «слова-ключа», а те саме розпізнавання: фраза → текст → нестроге
  порівняння з іменем. Підказка «Асистента звати …» у запиті до Whisper різко підвищує точність написання імені.
  Уві сні ім'я слухає мала модель на процесорі. Для очікування імені — окремий, чутливіший поріг гучності.
- **Голос.** OmniVoice з «відбитком» обраного голосу (`data/voice/offgrid-voice.pt`), 16 кроків, темп 1,1.
  Запасний — Piper у мовному сервісі: якщо якісний голос недоступний чи зламався посеред фрази, договорює він.
  Ліцензія OmniVoice — лише некомерційне використання.

## 8. Розмова, а не команди

Модель на 9 млрд параметрів сама по собі звучить як робот і часом каже «зараз відкрию» замість того, щоб
відкрити. Це виправляє код у `tone.js` і `agent.js`: прибирає чергове «чим ще допомогти?», один раз за запит
підштовхує модель, якщо вона лише оголосила намір, розпізнає прощання («повернусь потім») і не передає його
моделі. Час словами («пів на п'яту») рахує код, а не модель.

## 9. Острівець

Вікно прозоре попіксельно (прийом із DWM: порожня «область розмиття» змушує Windows поважати альфа-канал),
тому видно лише фігуру, яку малює сторінка. Сторінка повідомляє оболонці прямокутник, який зараз займає
острівець; решту вікна оболонка «вирізає», і кліки поруч доходять до програм під ним. Перший спосіб
(колір-ключ прозорості) не спрацював: WebView2 малюється окремим шаром. Розширення й стискання — анімація
всередині сторінки, саме вікно розміру не міняє, тому рух плавний.

## 10. Рішення, які пробували й відкинули

| Що | Чому відмовились |
|---|---|
| Electron | Smart App Control блокує непідписаний exe |
| Голоси Piper, StyleTTS2, RAD-TTS як основні | звучать «дешево» / не працювали |
| Окрема модель слова-ключа | ще одна залежність; розпізнавання вже є й дає точність |
| Дати Ollama самій ділити відеопам'ять | не знає про голос і розпізнавання → переповнення й 10 ток/с |
| Асистент сам пише собі інструменти | довільний код від моделі, якою можна керувати через прочитаний текст |
| Колір-ключ для прозорого вікна | не діє на WebView2 |

## 11. Чого бракує і що не перевірено

- Після етапів «відгук на ім'я», «острівець» і «пропозиції у білі списки» **не було незалежного рев'ю**.
- Захист від вбудованих інструкцій перевірено тестами логіки, але **не виміряно** на наборі справжніх атак.
- Прощання ловиться лише окремою короткою фразою.
- Ігри не зі Steam шукаються тільки за ярликом; головний файл гри вгадується.
- Папка проєкту успадковує права, за якими інші користувачі цього комп'ютера можуть змінювати файли.

## 12. Як перевіряти

`npm test` — тести логіки (безпека, налаштування, розмова, відеопам'ять, сон, пропозиції).
`npm run smoke`, `npm run tool-eval` — живі запити до моделі. `node scripts/wake-check.js` — відгук на ім'я.
Знімки інтерфейсу для розробки: змінні `OFFGRID_SHOT*` (див. `devScreenshot` у `main.js`).
